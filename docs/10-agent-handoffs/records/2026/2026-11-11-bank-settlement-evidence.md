## Цель

По запросу пользователя обеспечить проверяемое основание для проведения
существующей CRM-операции только после фактического исполнения банком. Для
monobank отдельно согласованы данные банковской выписки вместо автоматически
получаемой PDF-квитанции. Root реализует CRM-задачи, уникальное закрепление
банковской транзакции и изменение операции; эта подзадача выдаёт evidence.

## Изменения и причины

- `src/connectors/payments/settlement.py` — frozen DTO `BankAttachment`,
  `SettlementEvidence`, `ConfirmedPayment`, контракт `confirm_payment` и
  lazy registry. Общая проверка обязательных реквизитов и timezone-aware даты.
- `src/connectors/payments/privat24_settlement.py` — подтверждение только
  проведённого реального debit с точной ссылкой на созданный платёж, номером
  документа и полным совпадением реквизитов. Несколько кандидатов отклоняются.
  PDF запрашивается для подтверждённого референса после проверок.
- `src/connectors/payments/monobank_settlement.py` — состояние, точная операция
  и независимое подтверждение её присутствия на ожидаемом исходном счёте.
  Только исполненный расход без reverse с совпадающими реквизитами выдаёт
  evidence. Полученные данные выписки возвращаются без выдуманного PDF.
- `src/clients/privat24.py` — документированная пагинация с отказом на цикле,
  неполном ответе и лимите; ограниченные timeout; streaming PDF до 20 MiB с
  проверкой формата и безопасным именем. В ответ создания добавлен фактически
  отправленный payload и контекст создания без токена.
- `src/clients/monobank.py` — ограниченные read-only запросы состояния и выписки;
  полный лимит окна не считается доказанно полной выборкой. Сохраняются
  фактический sender IBAN и отправленный запрос; `source_account()` после
  автоподбора возвращает реальный выбранный счёт для существующего pipeline.
- `tests/test_payment_settlement.py` — 35 tests с синтетическими реквизитами,
  mocked HTTP и локально созданным минимальным PDF. Проверены положительные
  пути, отсутствие/расхождение полей, входящий платёж, pending/reverse,
  неоднозначность, невозможные даты, повреждённый PDF, пагинация, dry-run и
  сохранение контекста создания.

## Риски и незавершённое

Строгие проверки могут отправить документ на ручную проверку при изменении
формата банка, редактировании банковского платежа, неполных реквизитах или
неоднозначности. Поиск Privat24 ограничен последними 31 сутками и 100 страницами;
старые исполнения требуют отдельного согласованного reconciliation. Monobank
проверяет ограниченное account-scoped окно; его заполнение до лимита блокирует
автоматическое подтверждение. Полученная PDF-квитанция Privat24 ограничена
20 MiB. Последующий reverse не отменяется автоматически этим коннектором.

Уникальное закрепление transaction key за одной локальной задачей, opt-in новых
обработок, долговременное сохранение файлов, CRM retry и исключение historical
replay находятся в scope основного агента. DTO не выполняют CRM-запись сами.
