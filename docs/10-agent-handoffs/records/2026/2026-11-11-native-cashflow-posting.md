# Handoff: проведение Cashflow по подтверждению банка

- Агент: `Codex /root/crm_accountant_summary`
- Время UTC: `2026-11-11T18:33:19Z`
- Статус: `partial`
- Начальный commit: `2b576c98cfbd31581f5ec7401d409ca091321b84`
- Scope: read-only исследование native metadata, модуль проведения и unit tests.

## Цель

В рамках поручения пользователя от 11.11.2026 прикреплять документы и проводить
созданную ботом операцию после подтверждённой банковской оплаты. Подзадача:
воспроизвести штатный переход расхода с его договорными и ACL-эффектами,
не изменяя исторические операции и ручные финансовые правки.

## Исходное состояние

До реализации прочитаны production cutover, процесс новой синхронизации,
существующий connector и шаблон handoff. Рабочее дерево содержало параллельные
изменения основного агента и агента банковских подтверждений; они не изменялись
этим агентом. Проверки реальной CRM были только SELECT metadata, схемы и
агрегатов, без вывода бизнес-записей или credentials.

Установленные native факты:

- `ds_CashflowScript` нормализует расход в отрицательные Amount/BasicAmount,
  задаёт ActualDate при статусе «Выполнена», сужает ACL и вызывает
  `scr_ContractUtils.RefreshAmount`. PeriodID при переходе не меняется.
- `wnd_CashflowEditScript` запрещает обычное проведение по закрытому договору.
  SQL `tr_tbl_Cashflow_IU` сам не заменяет клиентские проверки и эффекты;
  выполняет изменение и журнальные записи.
- `RefreshAmount` суммирует BasicAmount проведённых доходов договора в
  PrePayment. База Debt — сумма BasicTotalAmount строк договора с множителем
  RentPeriodDays только для строк, у которых OfferingType.IsService=false;
  при IsWithTax применяется FloatValue системной настройки NonCashTax.
  Это налоговая настройка договора, не отдельное поле НДС платежа.
- Сохраняются только PrePayment и Debt. TotalAmount/TotalAmountWithTax —
  вычисляемые поля native query; `tsf_GetContractAmount` использует другую
  формулу отображения и не подменяет RefreshAmount.
- `tr_tbl_Contract_IU` сохраняет Contract и аудит. В исследованной цепочке
  изменений/INSERT-журналов внешних либо нетранзакционных действий не найдено.
- OwnerID ссылается на Contact; пользователь определяется через
  `tbl_AdminUnit.UserContactID`, IsGroup=0, UserIsEnabled=1. SQL-login бота
  не имеет собственного AdminUnit, поэтому права владельца требуют явной
  обработки. Native defaults для отсутствующего owner ACL: 1/1/0/0;
  существующие права не расширяются.
- Исключения для сужения CashflowRight определяет `sq_CashflowRight` в
  `tbl_Service.XMLData`: группа через UserInGroup и отдельный AdminUnit.
  Частные идентификаторы/имена не перенесены в исходники; параметры читаются
  по структуре native query.
- CashAccount не содержит IBAN либо ссылки на организацию; точного совпадения
  настроенных банковских счетов в проверенных доступных полях не найдено.
  По решению основного агента сохранено ранее принятое назначение CRM-счёта;
  новый модуль запрещает изменение CashAccount относительно исходного снимка.

## Изменения и причины

- `src/connectors/crm/terrasoft_posting.py` — `PostingService(connection).post`
  в транзакции вызывающего connector. Проверяются банковское подтверждение,
  UUID-маркер, статус, получатель и финансовый снимок; новые суммы становятся
  отрицательными, фактическая дата берётся из исполнения банка в Europe/Kyiv.
  Owner и аналитические поля сохраняются. Первоначально пустого получателя
  разрешено заполнить вручную только при точном совпадении кода с банком.
  Уже проведённая человеком операция не переписывается; ReservedID/LinkID,
  закрытый договор и финансовое расхождение требуют ручной проверки.
  Открытый договор блокируется и пересчитывается по native формуле; выполняются
  scoped ACL-эффекты и readback Cashflow/Contract после INSTEAD OF triggers.
- `tests/test_terrasoft_posting.py` — 20 проверок перехода, снимка, получателя,
  даты/знака, ручного проведения, договорной формулы, переполнения, closed
  contract, ACL и readback. Все значения тестов синтетические.
- Эта запись — источник handoff для интеграции основным агентом.

## Проверки

- Точная реализация `native_acl_exclusions` с helper `native_xml` выполнена

- Полный repository/regression suite, exact-SHA CI и интеграционные проверки
  на восстановленной изолированной CRM выполняет основной агент после сборки
  всех параллельных частей. Unit tests не доказывают готовность SQL rollout.

## Runtime, backup и rollback

Runtime не изменялся. SQL writes, deployment, commit и push этим агентом не
выполнялись. Временные исследовательские скрипты находились вне репозитория;
SQL metadata читались через существующее подключение без вывода URL/секретов.
Backup/restore, rehearsal и rollout находятся в scope основного агента.

## Риски и незавершённое

Реальные INSTEAD OF triggers, ACL-видимость владельца, транзакционный rollback
при частичной ошибке и конкуренция должны быть проверены на восстановленной
изолированной CRM. Отсутствующий/неоднозначный активный AdminUnit владельца,
неточный код получателя, неизвестный статус/metadata либо неподдерживаемые
связи намеренно завершаются manual review. Модуль не подписывает банковские
платежи, не меняет прошлые записи и не содержит собственного commit/retry.
Существующее одинаковое назначение CRM CashAccount для двух банков сохраняется
как ограничение ранее принятого mapping, а не как подтверждение совпадения IBAN.
